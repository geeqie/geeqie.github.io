Similarity Algorithms

This function is intended to find images with similar color content. For example when an image was saved at different compression levels or dimensions (scaled down/up) the contents are similar, but these files do not match by file size, dimensions, or checksum.

A 32 x 32 array is created for each image. Imagine the image cut into 1024 rectangles, 32 across and 32 down.

For each array element, the average value of all the red and the green and the blue pixels is computed and stored in the array. Therefore the array represents the average color of each corresponding part of the image.

This data is stored in a file with the same name as the image and with the extension .sim. It is stored in the same location as thumbnails. If many images are to be compared, run-time is reduced by having these .sim files already created. This can be done via Edit/Cache Maintenance or by the command line instruction: GQ_CACHE_MAINTENANCE=y geeqie --cache-maintenance=<path>

Standard Algorithm

To compare two images, each array element of each image is compared in turn. The computed value is the percent match of all elements of the two images. For this, simple comparisons are used - basically the value is an average of the corresponding array differences.

The value computed is in the range 0% to 100%.
100% for exact matches (an image is compared to itself) 0% for exact opposite images (compare an all black to an all white image)
Generally only a match of >85% is significant at all, and >95% is useful to find images that have been re-saved to other formats, dimensions, or compression.

If the Ignore Orientation checkbox on the Duplicates window is selected, images are also checked for 90°, 180°, 270°, rotations and mirror and flip. This will increase run-time.

Alternate Algorithm: Perceptual Hash (pHash)

Select Perceptual hash algorithm from the algorithm dropdown in the Duplicates window. The button shows Perceptual or Standard, and changing the selection restarts comparisons in open Duplicates windows. The selection also applies to image searches and similarity cache creation. This replaces the previous alternate algorithm.

Geeqie converts the 32 x 32 RGB grid to grayscale and computes a discrete cosine transform (DCT). The low-frequency 8 x 8 block describes coarse image structure. The constant brightness (DC) coefficient is excluded, and the remaining 63 coefficients are compared with their median to produce a 64-bit hash with one unused bit. This is a Geeqie-specific DCT pHash; hashes from other applications may use different preprocessing and are not interchangeable.

When pHash is selected, similarity cache creation stores eight hashes in each .sim file: one for every combination of right-angle rotation and reflection. These are derived from one DCT using coefficient transposition and sign changes. The RGB grid is retained, so switching back to the standard algorithm does not require rebuilding it. Existing caches without hashes are upgraded from their grids during cache maintenance or a similarity search, without decoding the source images again. Hashes already in a cache are retained when pHash is disabled.

Two images are compared by counting differing hash bits (Hamming distance). The similarity percentage is 100 x (1 - distance / 63). When Ignore Orientation is selected in the Duplicates window, the best match between both images' eight orientations is used; otherwise only the original orientation is compared. Considering both sets makes the score independent of image order and initial orientation, and requires up to 64 short hash comparisons per image pair. Exact hash matches score 100%, but this does not imply identical files or pixels.

The high (95%), medium (90%), and low (85%) thresholds allow at most 3, 6, and 9 differing bits respectively. These scores are not equivalent to the standard algorithm's percentages. Use the custom threshold to adjust results for your images. pHash ignores color and is tolerant of uniform brightness and contrast changes; unrelated images with similar coarse structure, including uniformly colored images, can match. Cropping and arbitrary-angle rotations are not explicitly handled.

Cached hashes make each comparison much cheaper than comparing RGB grids. Searches still compare image pairs, so large collections can take significant time. Enable pHash before an overnight cache-maintenance run to prepare all eight hashes in advance. The command line cache-maintenance program uses the saved algorithm selection, so save the configuration before starting it.
