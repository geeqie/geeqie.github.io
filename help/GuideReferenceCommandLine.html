Command Line Options

GEEQIE(1)

Geeqie — GTK based multiformat image viewer

DESCRIPTION

Geeqie is an interactive GTK based image viewer that supports multiple image formats, zooming, panning, thumbnails and sorting images into collections.

Generated for version:

Usage:

geeqie [OPTION…] [path…]

Geeqie is an image viewer.

Version: Geeqie 3.3

All other command line parameters are used as plain files if they exist, or a URL or a folder. The name of a collection, with or without either path or extension (.gqv) may be used.

If more than one folder is on the command line, only the last will be used.

If more than one file is on the command line:

If they are in the same folder, that folder will be opened and those files will be selected. If they are not in the same folder, a new Collection containing those files will be opened.

To run Geeqie as a new instance, use: GQ_NEW_INSTANCE=y[es] geeqie Normally a single set of configuration files is used for all instances. However, the environment variables XDG_CONFIG_HOME, XDG_CACHE_HOME, XDG_DATA_HOME can be used to modify this behavior on an individual basis e.g. XDG_CONFIG_HOME=/tmp/a XDG_CACHE_HOME=/tmp/b GQ_NEW_INSTANCE=y geeqie

To run or stop Geeqie in cache maintenance (non-GUI) mode use: GQ_CACHE_MAINTENANCE=y[es] geeqie --help Note that bash command line completion does not work in this mode.

Bash Completion

Geeqie provides Bash completion for command line options, action names, and image filenames. Type geeqie -- and press Tab twice to list available options.

Install the bash-completion package on the host and ensure it is enabled in your interactive Bash shell. On Ubuntu, install it with:

sudo apt install bash-completion

Snap

The Snap package registers completion for geeqie, geeqie.wayland, and geeqie.x11.

Start a new Bash shell after installing or updating the Snap. Use the command directly, such as geeqie --, rather than snap run geeqie --. Snap manages the completion script; you do not need to copy or source files from /snap/geeqie/current.

If completion does not work, type geeqie --, press Tab, and then run complete -p geeqie. Snap's completion handler is named _complete_from_snap. An older completion script from another Geeqie installation can take precedence; try a fresh shell after removing obsolete manual completion setup.

Flatpak

To use Geeqie's Bash completion with Flatpak, create a host-side command named geeqie and install the completion script on the host. A script installed inside the Flatpak is not automatically loaded by your host shell.

Create the directory $HOME/.local/bin if necessary, and save the following wrapper as $HOME/.local/bin/geeqie:

#!/bin/sh
exec flatpak run org.geeqie.Geeqie "$@"

Make it executable and ensure $HOME/.local/bin is on your PATH:

chmod +x "$HOME/.local/bin/geeqie"

Obtain the Geeqie source archive matching your Flatpak version from the release downloads. Install its completion script on the host, replacing the source path below with your source directory:

mkdir -p "${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions"
cp /path/to/geeqie-source/data/completions/geeqie \
   "${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions/geeqie"

Start a new Bash shell and check command -v geeqie to confirm it selects your wrapper. Type geeqie -- and press Tab twice. After triggering completion, complete -p geeqie should show _geeqie. These instructions register completion for the wrapper, not for arguments after flatpak run org.geeqie.Geeqie.

Update the completion script when you update the Flatpak. Filename completion uses files visible to the host shell; the Flatpak's filesystem permissions still determine which files Geeqie can open.

AppImage

An AppImage does not need to be extracted to use Bash completion. The completion script runs in the host shell, separately from the AppImage.

Make the AppImage executable and create a symbolic link named geeqie in a directory on your PATH. For example, replace the AppImage path below with its actual absolute path, and ensure $HOME/.local/bin is on your PATH:

chmod +x /absolute/path/to/Geeqie.AppImage
mkdir -p "$HOME/.local/bin"
ln -s /absolute/path/to/Geeqie.AppImage "$HOME/.local/bin/geeqie"

The geeqie-download-appimage.sh downloader already creates a geeqie link in $HOME/bin. If you use that link, ensure $HOME/bin is on your PATH.

Obtain the Geeqie source archive matching your AppImage version from the release downloads. Install its data/completions/geeqie file on the host, replacing the source path below with your source directory:

mkdir -p "${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions"
cp /path/to/geeqie-source/data/completions/geeqie \
   "${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions/geeqie"

Start a new Bash shell, type geeqie --, and press Tab twice. Use the command named geeqie; the script does not register completion for arbitrary AppImage filenames. After triggering completion, complete -p geeqie should show _geeqie.

Update the completion script when you update the AppImage so that the available options and actions stay current. If you have already extracted an AppImage, you can use its squashfs-root/usr/share/bash-completion/completions/geeqie file instead of the source copy.

Independent Instances

Normally, launching Geeqie again sends the command to the running application instance. Opening another window does not create an independent instance. Ctrl+Q quits that instance and closes all its windows; Ctrl+W closes only the current window, quitting the instance if it is the last main window.

To start an independent application instance, use:

GQ_NEW_INSTANCE=y geeqie /path/to/folder

Quitting this instance does not close windows belonging to another instance. By default, independent instances share configuration and state files. Each instance saves configuration on exit, so the last one to exit can overwrite settings saved by another instance.

To keep a separate persistent configuration, set a different configuration root:

XDG_CONFIG_HOME="$HOME/.config/geeqie-work" GQ_NEW_INSTANCE=y geeqie /path/to/folder

This instance uses a separate configuration under $HOME/.config/geeqie-work/geeqie. The XDG_CACHE_HOME and XDG_DATA_HOME environment variables can also be set to separate cache and data locations. Separate configurations do not isolate changes made to image files or their metadata.
